# 前端 API 路由适配方案

## 背景

后端 nginx 新增了模块前缀路由规则：

| 浏览器请求前缀 | Nginx 动作 | 后端收到 |
|---|---|---|
| `/auth/...` | 去掉 `/auth/` → auth-service | `/api/v1/auth/login` |
| `/conversation/...` | 去掉 `/conversation/` → conversation-service | `/api/v1/sessions` |
| `/knowledge/...` | 去掉 `/knowledge/` → knowledge-service | `/api/knowledge/docs` |
| `/ws/...` | 新增 location，代理 WS → conversation-service | `/ws/agent?...` |

旧前端路径缺少模块前缀（如 `/api/v1/auth/login`），需要改为 `/auth/api/v1/auth/login`。

## 核心策略

**为每个后端服务创建专用 HTTP client**，baseURL 设为模块前缀（`/auth`、`/conversation`、`/knowledge`），各 API 文件只需切换 import 的 client，路径本身不变。

## 变更清单

### 1. `apps/src/api/request.ts` — 新增 4 个专用 client

```typescript
// 认证服务 (auth-service:8083)
export const authClient = createRequestClient('/auth', { responseReturn: 'data' });
export const authBaseClient = new RequestClient({ baseURL: '/auth' });

// 对话服务 (conversation-service:8082)
export const conversationClient = createRequestClient('/conversation', { responseReturn: 'data' });

// 访客公开接口 (conversation-service, 无 token 注入)
export const publicConversationClient = createRequestClient('/conversation', { responseReturn: 'data' });

// 知识库服务 (knowledge-service:8081)
export const knowledgeClient = createRequestClient('/knowledge', { responseReturn: 'data' });
```

### 2. `apps/vite.config.ts` — 开发代理规则更新

```
/auth/api/v1         → auth-service:8083        (原 /api/v1 兜底)
/conversation/api/v1 → nginx:8090                (新增，覆盖 sessions/chat/dashboard/dit)
/knowledge/api       → knowledge-service:8084    (原 /api/knowledge)
/ws                  → nginx:8090, ws:true       (不变)
```

### 3. API 文件 — 切换 import 的 client

| 文件 | 旧 client | 新 client | 说明 |
|---|---|---|---|
| `core/auth.ts` | `requestClient`, `baseRequestClient` | `authClient`, `authBaseClient` | 登录/刷新/退出/权限码 |
| `core/user.ts` | `requestClient` | `authClient` | 用户信息 |
| `core/menu.ts` | `requestClient` | `authClient` | 菜单 |
| `ai-model/index.ts` | `requestClient` | `authClient` | AI 模型配置 |
| `system-config/index.ts` | `requestClient` | `authClient` | 系统配置 |
| `dit/index.ts` | `requestClient` | `conversationClient` | DIT 管理 → conversation |
| `session/index.ts` | `rawRequestClient`, `publicRequestClient` | `conversationClient`, `publicConversationClient` | 会话/队列 |
| `dashboard/index.ts` | `rawRequestClient` | `conversationClient` | Dashboard 统计 |
| `knowledge/index.ts` | `rawRequestClient` | `knowledgeClient` | 知识库文档 |
| `knowledge/chunk.ts` | `rawRequestClient` | `knowledgeClient` | 知识库 Chunk |

### 4. 特殊 URL 修复

#### SSE EventSource (`session/index.ts`)
```typescript
// 旧: `/api/v1/sessions/events?token=...`
// 新: `/conversation/api/v1/sessions/events?token=...`
```

#### AI Summary SSE (`session/index.ts`)
```typescript
// 旧: `/api/v1/sessions/${sessionId}/ai-summary/stream?token=...`
// 新: `/conversation/api/v1/sessions/${sessionId}/ai-summary/stream?token=...`
```

#### 文档预览 URL (`knowledge/index.ts`)
```typescript
// getDocPreviewUrl: return `/knowledge/api/knowledge/docs/${docId}/preview`
// getDocRawContentApi: fetch(`/knowledge/api/knowledge/docs/${docId}/preview`)
```

### 5. `.env.development` / `.env.production` — 不需要改

`VITE_GLOB_API_URL` 保持不变，因为新的专用 client 不依赖这个全局变量。

## 不涉及 WebSocket 前端修改

用户确认在 nginx 中新增 `/ws` location 代理 WebSocket 到 conversation-service。前端 WebSocket 路径（`/ws/agent`、`/ws/chat/:id`）不变。

## 风险点

- `session/index.ts` 还导出了 `WsChatMessage` 等类型，被多处 import，只改路径不影响类型
- `useAgentWsChannel.ts` 的 `buildWsUrl()` 用 `/ws/agent?token=`，无需改动
- `connectVisitorWs` / `connectAgentWs` 的 WS 路径无需改动
- 公共 client `publicConversationClient` 需要确保不注入 token（参考 `publicRequestClient` 的实现）
